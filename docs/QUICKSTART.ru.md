# Загрузка и структура скрипта

Skeet загружает каждый файл `.lua` из корня `%LOCALAPPDATA%\skeet` как самостоятельный скрипт. Создайте свой файл в этой папке или через **Configs → New Lua script**. Выберите файл и включите **Enabled**. После правок перечитайте файл командой **Reload script**.

## Что происходит при загрузке

Сначала выполняется верхний уровень файла. Здесь регистрируют обработчики событий и создают контролы с постоянными идентификаторами. Отрисовка выполняется в `paint`. Событие `shutdown` даёт скрипту возможность освободить собственные ресурсы. При ошибке раскройте первый traceback в журнале Lua. [События](EVENTS.ru.md) · [Обработка ошибок и бюджеты](RUNTIME.ru.md).

## Где хранятся файлы

| Путь от корня Skeet | Назначение |
|---|---|
| `<имя>.lua` | Точка входа скрипта |
| `<имя>.lua.json` | Значения модуля storage этого скрипта |
| `resources/` | Ресурсы по имени для графического API |
| `fonts/` | Файлы шрифтов по пути с префиксом `fonts/` |
| `skeetles/` | Изображения по пути с префиксом `skeetles/` |
| `muzon/`, `sounds/` | Звуки по имени или с явным префиксом `sounds/` |

Значения контролов и бинды сохраняет конфигурация Skeet. Для выбора каталога шрифтов или текстур действуют правила конкретной функции. [Графика](RENDER.ru.md) · [Управление настройками](SETTINGS.ru.md).

## Подсказки IDE

Подключите [api.lua](api.lua) и [ffi.lua](ffi.lua) как библиотеку деклараций редактора. Они описывают имена, типы, необязательные аргументы и результаты. Для проверки доступных возможностей в запущенной среде служит `api.capabilities()`. [Справочник](API_INDEX.ru.md).
